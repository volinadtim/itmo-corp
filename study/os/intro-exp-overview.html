1. Смысл лабы и вариант

Есть файл на диске, в нём записи (вершины графа). Программа идёт по цепочке: прочитала вершину, узнала номер следующей, прыгнула к ней. В режиме записи ещё и увеличивает число в каждой вершине на 1. Это модель базы данных, которая ходит по записям.

Одну и ту же работу делают две программы, отличающиеся только способом доступа к файлу:

graph_traverse
Обычные системные вызовы: lseek() встать на позицию, read() прочитать, write() записать. Каждое обращение — просьба к ядру.
graph_traverse_mmap
Файл mmap()-ом отображается в память процесса, дальше программа читает и пишет его как обычный массив. Ядро подгружает страницы само, когда к ним обращаются.

Лаба учит не столько «что быстрее», сколько как честно мерить: паспорт системы, контроль окружения, гипотеза до замеров, серия из N запусков, доверительный интервал, вывод.

Эксперимент — это управляемое изменение одного фактора (здесь — размера файла) при фиксации остальных условий с последующей статистической оценкой отклика (времени обхода). Результат каждой конфигурации — точечная оценка математического ожидания времени с доверительным интервалом, а не единичное измерение.

2. Память: виртуальная память, страницы, page fault

Каждый процесс видит свою «виртуальную» память: адреса от 0 до огромного числа. Реальная оперативная память (физическая) раздаётся кусками по 4 КиБ — страницами. Таблица страниц говорит: «виртуальная страница № X лежит в физической рамке № Y» (или «пока нигде»). Процессор переводит адреса сам (блок MMU), а последние переводы держит в маленьком кэше — TLB.

Если в таблице для страницы «нет», процессор бросает исключение — страничный промах (page fault). Ядро его обрабатывает:

  • minor fault — данные уже в RAM (например, в page cache), надо лишь вписать строчку в таблицу страниц. Микросекунды.
  • major fault — данных в RAM нет, надо читать с диска. Сотни микросекунд на NVMe, миллисекунды на HDD.
Страничный промах — синхронное исключение процессора при обращении к виртуальной странице, для которой в таблице страниц нет действительного отображения или права доступа не допускают операцию. Обработчик ядра либо устанавливает отображение на уже резидентную рамку (minor), либо инициирует ввод-вывод для загрузки страницы с носителя (major), либо посылает процессу SIGSEGV, если адрес не принадлежит ни одной области памяти.

Шкала задержек (держи в голове порядки)

Вывод из шкалы: поход к диску в тысячи раз дороже всего, что делает процессор. Поэтому в моём варианте время почти целиком — это ожидание диска.

3. Ввод-вывод: read/write, page cache, O_DIRECT

Обычно ядро держит прочитанные куски файлов в свободной RAM — это page cache (в free -h колонка buff/cache). Второй read() того же места приходит из памяти, диск не трогается. write() тоже по умолчанию лишь пишет в page cache и помечает страницу грязной (dirty); на диск её позже сбросит фоновый поток ядра (writeback).

O_DIRECT — флаг при open(): «читай и пиши прямо с диска в мой буфер, page cache не используй». Цена: диск работает блоками, поэтому адрес буфера, смещение в файле и длина должны быть кратны размеру блока (у нас 512 байт). Наша вершина — 24 байта, поэтому программа читает целый блок в 512 Б, а для записи делает read-modify-write: прочитать блок → поменять 8 байт → записать блок обратно.

Страничный кэш (page cache) — область оперативной памяти ядра, в которой хранятся страницы файлов, отображённые на их смещения. Буферизованный ввод-вывод копирует данные между page cache и буфером процесса; изменённые страницы помечаются как грязные и асинхронно сбрасываются на носитель механизмом writeback. Флаг O_DIRECT предписывает выполнять передачу непосредственно между буфером процесса и устройством, минуя page cache, при условии выравнивания адреса, смещения и длины по логическому блоку устройства. O_DIRECT не гарантирует долговечности записи (для этого нужен O_SYNC/fsync) и не отключает внутренний кэш самого накопителя.

drop_caches: sync; echo 3 | sudo tee /proc/sys/vm/drop_caches — сначала сбросить грязные страницы на диск, потом выкинуть чистые страницы из page cache (и dentry/inode-кэши). Так каждый запуск начинается с холодного кэша.

4. mmap

char *p = mmap(NULL, size, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);
p[100] += 1;        // это обращение к памяти, а не системный вызов

После mmap() никаких данных ещё не прочитано. Ядро лишь записало: «этот диапазон адресов = этот файл». При первом обращении к странице — page fault, ядро находит страницу в page cache (или читает с диска, захватив заодно соседние — readahead) и вписывает её в таблицу страниц. Дальше доступ — обычная скорость памяти.

MAP_SHARED: изменения видны всем и попадают в файл (через тот же page cache). При записи: страница сначала отображается только на чтение; первая запись вызывает ещё один (minor) fault, ядро помечает страницу грязной и разрешает запись. Отсюда в режиме --write примерно два промаха на страницу.

Главный нюанс лабы. У mmap нет аналога O_DIRECT: отображение всегда работает через page cache. Поэтому в graph_traverse_mmap ключ --no-cache — это лишь советы ядру: madvise(MADV_SEQUENTIAL) в начале (агрессивный readahead), а в конце msync(MS_SYNC) (синхронно записать грязные страницы) и madvise(MADV_DONTNEED) (выкинуть отображение). Это есть даже в справке программы: «advisory madvise only; mmap still uses the page cache». Значит, сравнение read против mmap «без кэша» — сравнение двух разных вещей.
mmap(2) создаёт в адресном пространстве процесса отображение области файла. Страницы загружаются лениво — по страничным промахам при первом обращении. При MAP_SHARED изменения записываются в общие страницы page cache и попадают в файл при writeback или явном msync(2). madvise(2) передаёт ядру рекомендации о характере доступа (MADV_SEQUENTIAL, MADV_RANDOM, MADV_DONTNEED); ядро вправе их не выполнять, и MADV_DONTNEED для файлового отображения снимает отображение у процесса, но не гарантирует вытеснение страниц из page cache.

5. Обе программы и граф изнутри

Файл: заголовок, затем записи по 24 байта: value (8 Б), degree (4 Б), заполнитель, child (8 Б, номер следующей вершины). Адрес вершины i = заголовок + 24·i. Топология Rand: graphgen.py --topology chain -b 0.5 --min-step-pages 2 — цепочка проходит все вершины, но каждый прыжок минимум на 2 страницы (8 КиБ), половина прыжков — назад.

Что происходит на одной вершине (read-версия, --write --no-cache)

lseek(blk) ; read(512 Б)    # прочитать блок с вершиной       → диск: чтение
lseek(blk) ; read(512 Б)    # RMW: перечитать тот же блок      → диск: чтение
lseek(blk) ; write(512 Б)   # RMW: записать блок с value+1     → диск: запись

6 системных вызовов и 3 операции с диском на каждую вершину: 2 чтения + 1 запись. Это видно в счётчиках /usr/bin/time -v: «File system inputs» ≈ 2·(число вершин), «outputs» ≈ 1·(число вершин), в единицах по 512 Б. Для 1M: 90 736 и 43 697 при 43 689 вершинах. Сходится.

mmap-версия на той же вершине делает просто node->value++ в памяти. Системные вызовы только по краям: open, mmap, madvise, msync, madvise, munmap.

Произвольное (voluntary) переключение контекста происходит, когда процесс сам блокируется в ожидании ресурса (например, завершения ввода-вывода); принудительное (involuntary) — когда планировщик вытесняет процесс по истечении кванта или ради более приоритетной задачи. У read-версии с O_DIRECT около трёх произвольных переключений на вершину — по одному на каждую синхронную операцию с устройством.

7. Статистика

Каждый запуск даёт немного разное время. Мы оцениваем «истинное» среднее по выборке из N запусков:

x̄ = (1/N)·Σxᵢ                     среднее
s = √( Σ(xᵢ − x̄)² / (N−1) )       стандартное отклонение (разброс запусков)
SE = s / √N                        стандартная ошибка (неточность среднего)
ДИ95 = x̄ ± t(0.975; N−1) · SE      доверительный интервал, t для N=10 ≈ 2,26
N ≈ (t · s / E)²                   сколько нужно запусков для полуширины E
Доверительный интервал уровня 95% — интервал, построенный по выборке процедурой, которая в 95% повторений эксперимента накрывает истинное математическое ожидание. При неизвестной дисперсии и малом N используется квантиль распределения Стьюдента с N−1 степенями свободы. ДИ характеризует неопределённость оценки среднего и сужается как 1/√N; стандартное отклонение характеризует разброс отдельных измерений и с ростом N не уменьшается.

Гистограмма против KDE. Гистограмма раскладывает точки по корзинам, форма зависит от ширины и границ корзин. KDE (оценка плотности ядром) кладёт на каждую точку маленький «холмик» (гауссиану) и суммирует их: получается гладкая кривая, зависящая от ширины холмика (bandwidth). Обе нужны, чтобы увидеть, что распределение времени не нормальное: у нас оно двугорбое из-за диска.
