# Merge

В данном задании вам необходимо написать утилиту на C++ для слияния отсортированных файлов.

## Интерфейс

Аргументами командной строки подаются пути до входных файлов.

Каждый из входных файлов состоит из лексикографически отсортированной последовательности _строк_.
Строкой считается максимальная по включению последовательность байтов, кроме `\r` и `\n`, плюс завершающий _перенос строки_.
Переносом строки считается любая из следующих последовательностей байтов: `\n`, `\r`, `\r\n`.
Если непустой файл завершается не переносом строки, программа должна работать так, будто он там есть.

Все строки из всех входных файлов записываются в поток стандартного вывода (_stdout_) в лексикографическом порядке.
В качестве переноса строки при выводе всегда используется `\n` (поскольку поток стандартного вывода всегда открыт в текстовом режиме, на некоторых системах этот `\n` может быть неявно трансформирован в другие переносы строки).

При любых ошибках программа завершается с ненулевым кодом возврата и пишет информативное сообщение в поток стандартного вывода ошибок (_stderr_).

Таким образом, поведение очень похоже на `sort -m`.

### Пример

Допустим, в файле `foo.txt` содержатся строки `apple` и `orange`, в файле `bar.txt` строки `apple` и `banana`, а файла `baz.txt` не существует вовсе.

#### Пример 1

```bash
$ ./merge foo.txt bar.txt
```

должен вывести:

```
apple
apple
banana
orange
```

и завершиться с кодом 0.

#### Пример 2

```bash
$ ./merge foo.txt bar.txt baz.txt
```

должен вывести сообщение об ошибке, информирующее о том, что файла `baz.txt` не существует, и завершиться с ненулевым кодом.

## Требования к решению

Точка входа в программу располагается в [src/main.cpp](src/main.cpp).

Вспомогательные структуры и алгоритмы располагайте в других `.h` и `.cpp` файлах по соседству.
В качестве примера в шаблоне уже присутствуют [dynamic-string.h](src/dynamic-string.h) и [dynamic-string.cpp](src/dynamic-string.cpp) для структуры `DynamicString` и связанных с ней функций.

### Эффективность

Допустимая асимптотика: `O(N * M * log K + K)`, где:

* `N` &mdash; суммарное кол-во строк во входных файлах;
* `M` &mdash; максимальная из длин строк;
* `K` &mdash; количество входных файлов.

Суммарный объём файлов может быть большим, вы не должны расходовать более `O(M * K)` байтов памяти.

### Ограничения

Данное задание призвано продемонстрировать сложности разработки классического низкоуровневого кода в отсутствие высокоуровневых механизмов для управления ресурсами и обработки ошибок.

* Во-первых, это поможет вам лучше понять мотивацию соответствующих механизмов, когда вы начнёте их использовать в следующих заданиях.
* Во-вторых, довольно много кода на Си уже написано в подобном стиле, с чем вы, увы, можете столкнуться в жизни даже при работе с кодовой базой на C++, например как следствие миграций такого кода с Си, так что полезно в таком коде тоже уметь разобраться.

Поэтому к решению предъявлены следующие ограничения:

* Нужно использовать функции из `<cstdio>`, а не I/O streams из C++.
* Для выделения памяти нужно использовать семейство функций `std::malloc`.
* Нельзя использовать исключения, а также части стандартной библиотеки, оперирующие ими.
* Нельзя определять классы с нетривиальными деструкторами, а также использовать классы из стандартной библиотеки, имеющие нетривиальные деструкторы, например:
  * запрещены: `std::string`, `std::vector<T>`, `std::fstream`;
  * разрешены: `std::array<T, N>`, `std::span<T, N>`.

> [!TIP]
> Данные ограничения соответствуют тому, что вы проходили на лекциях на момент выкладывания задания.
> Если какие-то слова вам не знакомы &mdash; это нормально, просто не используйте те механизмы, о которых ничего не знаете.
> В частности, если вы не знаете, что такое (не)тривиальный деструктор, но поняли дух задания, скорее всего вы на это ограничение случайно не наткнётесь.

## Сборка и тестирование

### CMake

Вам предлагается начать использовать систему автоматизации сборки `CMake`. Она широко распространена, а также будет использована во всех последующих заданиях.

О том, как с ней работать, можно прочитать [на сайте курса](https://pages.ct.itmo.ru/cpp/course/env.html#cmake).

Процесс сборки также может быть автоматизирован при помощи IDE, информацию о чём вы также найдёте по ссылке выше.

### Тестирование

Тесты реализованы на Python при помощи библиотеки _pytest_.

Для их запуска можно воспользоваться командой (потребуется установить `pytest` через ваш любимый пакетный менеджер):

```bash
python3 -m pytest test \
  --exe "build/${preset_name}/src/merge"
```

Полезные флаги:

* `-k <pattern>` &mdash; запустить не все тесты, а только с матчащимся именем;
* `-v` &mdash; увеличить вербозность (количество выводимой информации).

### Вспомогательные скрипты

Для вашего удобства команды для сборки и тестирования вынесены в скрипты в директории [scripts/](scripts/):

* `scripts/build.sh` &mdash; сконфигурировать и собрать программу;
* `scripts/run.sh <args...>` &mdash; запустить собранную программу с переданными аргументами;
* `scripts/test.sh [args...]` &mdash; запустить тесты, опционально передав дополнительные опции в _pytest_.

По умолчанию в них используется пресет `RelWithDebInfo`, а артефакты сборки располагаются в `build-RelWithDebInfo`.
Можно задать другой пресет, выставив переменную окружения `PRESET`, например:

```bash
$ PRESET=SanitizedDebug scripts/build.sh
$ PRESET=SanitizedDebug scripts/run.sh file1.txt file2.txt
$ PRESET=SanitizedDebug scripts/test.sh
```

### Docker (как в CI)

Вы также можете максимально приблизиться к CI, используя [наши Docker-образы](https://gitlab.ct.itmo.ru/cpp/containers).

Например:

```bash
$ docker run -t --rm -v .:/src -w /src -u $(id -u):$(id -g) \
  -e PRESET=SanitizedDebug cr.ct.itmo.ru/cpp/containers/gcc:15 \
  scripts/build.sh
```

```bash
$ docker run -t --rm -v .:/src -w /src -u $(id -u):$(id -g) \
  -e PRESET=SanitizedDebug cr.ct.itmo.ru/cpp/containers/gcc:15 \
  scripts/test.sh
```

Аналогично можно использовать образ с Clang, просто заменив имя образа на `cr.ct.itmo.ru/cpp/containers/clang:22`.
