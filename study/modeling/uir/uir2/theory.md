# УИР 2: теория к защите с нуля

Объяснение идёт от простого к сложному, и все примеры взяты из моего варианта 60/60/31.

## 1. Что такое СМО

Система массового обслуживания состоит из трёх вещей:

- **заявки** приходят в случайные моменты; λ = 0,6 заявки в секунду в среднем;
- **прибор** обслуживает одну заявку за раз; обслуживание длится в среднем b = 10 с, значит, прибор
  может выполнять μ = 1/b = 0,1 заявки в секунду;
- **накопитель** (очередь) держит заявки, пока прибор занят; ёмкость r. Если места нет, заявка теряется.

**Нагрузка** y = λ·b показывает, сколько работы приходит на прибор. y = 1 значит «приходит ровно
столько, сколько прибор успевает». y > 1 значит перегрузку: часть заявок неизбежно теряется.

В моём варианте заявка сразу выбирает прибор: к П1 с вероятностью 0,75, к П2 с 0,15, к П3 с 0,1.
Поэтому у каждого прибора свой поток: λ₁ = 0,6·0,75 = 0,45, λ₂ = 0,09, λ₃ = 0,06.

## 2. Состояние и граф переходов на самом простом примере

Возьмём один П1 без накопителя. У него всего два состояния:

- **0**: прибор свободен;
- **1**: прибор занят, новая заявка теряется.

Из 0 в 1 система переходит, когда приходит заявка: интенсивность λ₁ = 0,45.
Из 1 в 0 переходит, когда заканчивается обслуживание: интенсивность μ = 0,1.

```
      λ₁ = 0,45
  0  ────────►  1
     ◄────────
      μ = 0,1
```

Это и есть **размеченный граф переходов**: вершины соответствуют состояниям, стрелки переходам,
на стрелках написаны интенсивности.

## 3. Стационарные вероятности: «сколько вытекло, столько втекло»

Через долгое время система «устаканивается»: доля времени, которую она проводит в каждом состоянии,
перестаёт меняться. Эти доли называются **стационарными вероятностями** p₀, p₁, …

Правило для каждого состояния: **поток вероятности из него равен потоку в него**.

Для состояния 0: уходим из него с интенсивностью λ₁, приходим из 1 с интенсивностью μ:

```
p₀·λ₁ = p₁·μ        и        p₀ + p₁ = 1
```

Отсюда p₁ = y/(1+y) = 4,5/5,5 = **0,818**. Это число есть в отчёте: П1 занят 82 % времени
и теряет 82 % своих заявок, поэтому у обеих систем такие большие потери.

## 4. Прибор с накопителем

П2 в СИСТЕМЕ_1 имеет накопитель на 3 места. Состояние задаётся числом заявок k = 0…4
(одна на обслуживании и до трёх в очереди):

```
   λ₂     λ₂     λ₂     λ₂
0 ───► 1 ───► 2 ───► 3 ───► 4
  ◄───   ◄───   ◄───   ◄───
   μ      μ      μ      μ
```

В состоянии 4 накопитель полон, и стрелки λ₂ из него нет: пришедшая заявка теряется.

## 5. Как из приборов получается вся система

Каждая заявка сразу уходит к своему прибору, поэтому приборы друг другу не мешают. Тогда
состояние всей системы описывается просто набором состояний приборов (k₁, k₂, k₃):

- k₁ ∈ {0, 1}, у П1 2 варианта;
- k₂ ∈ {0…4}, у П2 5 вариантов;
- k₃ ∈ {0, 1}, у П3 2 варианта.

Всего 2·5·2 = **20 состояний**. За один бесконечно малый момент меняется только одна координата:
либо пришла одна заявка, либо закончилось одно обслуживание. Например, из (1, 2, 0) можно попасть:

- в (1, 3, 0), если пришла заявка к П2 (λ₂);
- в (1, 2, 1), если пришла заявка к П3 (λ₃);
- в (0, 2, 0), если закончил П1 (μ);
- в (1, 1, 0), если закончил П2 (μ).

Заявка к П1 из этого состояния ничего не меняет: П1 занят, накопителя нет, заявка теряется.

## 6. Матрица интенсивностей G и система PG = 0

Матрица G записывает тот же граф в виде таблицы: g_ij равно интенсивности стрелки из Eᵢ в Eⱼ.
На диагонали стоит минус сумма строки, g_ii = −(сумма всех стрелок из Eᵢ).

Уравнение PG = 0 означает то же самое правило «вытекло = втекло», записанное сразу для всех
20 состояний. Уравнений 20, но одно из них следует из остальных, поэтому его заменяют условием
p₁ + … + p₂₀ = 1. Решение системы и есть форма 1 (таблица вероятностей).

## 7. Характеристики через вероятности

Когда вероятности известны, каждая характеристика получается сложением вероятностей нужных
состояний. Для прибора i:

| Что | Как считается | Смысл |
|---|---|---|
| загрузка ρᵢ | сумма p по состояниям, где kᵢ ≥ 1 | доля времени, когда прибор занят |
| очередь lᵢ | сумма (kᵢ − 1)·p по состояниям, где kᵢ ≥ 2 | сколько заявок в среднем ждёт |
| число заявок mᵢ | сумма kᵢ·p | сколько заявок в среднем у прибора |
| потери πᵢ | сумма p по состояниям, где накопитель полон | доля потерянных заявок |
| производительность λ'ᵢ | λᵢ·(1 − πᵢ) | сколько заявок в секунду реально обслуживается |
| ожидание wᵢ | lᵢ / λ'ᵢ | сколько секунд заявка стоит в очереди |
| пребывание uᵢ | mᵢ / λ'ᵢ | сколько секунд заявка проводит в системе |

**Почему потери равны вероятности того, что накопитель полон.** Поток простейший: заявка приходит
в случайный момент и видит систему в «типичном» состоянии. Значит, она застаёт полный накопитель
ровно с той вероятностью, с какой система в нём находится.

Для системы в целом очереди и числа заявок складываются: L = l₁ + l₂ + l₃. Загрузка берётся
средняя по приборам.

## 8. Проверка формулами Литтла

В расчёте формулы Литтла не участвуют, поэтому ими можно проверить результат:

- ρᵢ = λ'ᵢ·b: прибор занят ровно столько, сколько нужно на принятые заявки;
- mᵢ = lᵢ + ρᵢ: заявки у прибора складываются из ждущих и обслуживаемой;
- uᵢ = wᵢ + b: время в системе складывается из ожидания и обслуживания.

У меня все три сошлись для каждого прибора.

## 9. Эрланг: как сделать марковский процесс из не марковского

Марковский процесс требует экспоненциальных времён: только у экспоненты нет памяти, то есть
неважно, сколько заявка уже обслуживается, шанс закончить в ближайший момент всегда один и тот же.

У П2 в СИСТЕМЕ_2 обслуживание по закону Эрланга 2-го порядка, и он не экспоненциальный.
Трюк такой: время по Эрлангу 2-го порядка равно сумме **двух экспоненциальных фаз**. Каждая фаза
длится в среднем b/2 = 5 с, то есть её интенсивность 2μ = 0,2. Если запоминать в состоянии,
на какой фазе заявка, процесс снова становится марковским.

Поэтому состояние П2 записывается как «число заявок и фаза»: 0, 1₁, 1₂, 2₁, 2₂, … 4₁, 4₂.
Получается 9 вариантов, вместе с П1 всего 2·9 = **18 состояний**. Переходы П2:

- 3₁ → 3₂ (2μ): закончилась первая фаза;
- 3₂ → 2₁ (2μ): закончилась вторая фаза, заявка ушла, следующая начинает с первой фазы;
- 3₁ → 4₁ (λ₂): пришла заявка, фаза у обслуживаемой не меняется.

## 10. Что вышло и почему

| | СИСТЕМА_1 | СИСТЕМА_2 |
|---|---|---|
| нагрузка на П2 | 0,9 | 1,5 |
| суммарная очередь L | **1,03** | 1,89 |
| потери | 0,675 | 0,705 |

Критерий (д) требует минимальной очереди, поэтому выигрывает СИСТЕМА_1. Причина простая:
во второй системе нет П3, и его 10 % заявок тоже идут на П2. На П2 приходит 25 % потока вместо 15 %,
y₂ > 1, и очередь растёт.

Сам Эрланг почти ни на что не влияет. С экспоненциальным П2 очередь была бы 1,83 вместо 1,89.
